## The big idea

Wi-Fi is a **shared, multi-access** link like Ethernet (Lesson 19), but over **radio** instead of a cable. Radio brings two new problems:

1. **More errors**, from noise and interference, so frames must be **acknowledged**.
2. **Nodes can't always hear each other**, which creates the **hidden node** and **exposed node** problems.

---

## 1. What 802.11 is (slide 56)

- The **most successful local wireless networking** technology: the **Wireless LAN (WLAN)**.
- **Licence-exempt:** it uses the **ISM band** (Industrial, Scientific and Medical radio frequencies), so you don't need a licence to run one.
- **Standardised by the IEEE.**
- The **Wi-Fi Alliance** is an industry organisation that promotes **interoperability, compatibility and standard compliance**. It's why a laptop from one company works with a router from another.

## 2. Network types (slides 57–58)

### Key terms

| Term | Stands for | Meaning |
|---|---|---|
| **STA** | Station | A user device (laptop, phone) |
| **AP** | Access Point | A station with access to an **external network** (e.g. the wired network or the Internet) |
| **BSS** | Basic Service Set | A group of stations that can communicate. Its size is set by how far the radio signal reaches. |
| **SSID** | Service Set Identifier | The advertised **network name**, e.g. "UCDwireless" |
| **ESS** | Extended Service Set | Several BSSs joined together into one large network |

### Two kinds of BSS

```
Independent BSS (ad-hoc)              Infrastructure BSS

   STA ─── STA                              STA
    │  ╲  ╱  │                               │
    │   ╲╱   │                       STA ─── AP ─── STA
    │   ╱╲   │                               │
   STA ─── STA                              STA
 devices talk directly                 all traffic goes through the AP
```

| | Independent BSS (ad-hoc) | Infrastructure BSS |
|---|---|---|
| Access point? | ❌ No | ✅ Yes |
| Who talks to whom | Stations talk **directly** to each other | Stations talk **through the AP** |
| Example | Two phones sharing a file directly | Your home Wi-Fi router |

### Extended Service Sets (slide 58)

One BSS only covers a **limited area**. An **ESS** joins several BSSs to make an **arbitrarily large** network:

```
              Internet
                 │
              Router
                 │
  ══════ Distribution system (usually an Ethernet backbone) ══════
     │             │             │             │
    AP            AP            AP            AP
   BSS1          BSS2          BSS3          BSS4
          all advertise the same SSID, e.g. "UCDwireless"
```

- **All the APs advertise the same SSID**, so to a user it looks like one network.
- The BSSs are joined by a **distribution system**: a **backbone network** that forwards packets between APs. **Ethernet** is the most common.
- This lets users **move between APs** without losing the connection.

> **Real-world example:** a campus Wi-Fi network. You walk from the library to a lecture hall and your phone switches APs without you noticing, because every AP is called "UCDwireless".

## 3. Where 802.11 sits in the OSI model (slide 59)

| Layer | Examples |
|---|---|
| Application, Presentation, Session | HTTP, FTP, SSH |
| Transport | TCP, UDP, SCTP |
| Network | IPv4, IPv6 |
| **Data link** | Ethernet, **802.11**, ISDN, ATM |
| **Physical** | **802.11**: wired, wireless, optical |

**802.11 covers both the physical layer and the data link (MAC) layer.** It replaces the cable, but everything above it (IP, TCP, HTTP) works exactly the same. That's the point of layering (Lesson 3): you can change one layer without changing the whole system.

## 4. RF link quality: why Wi-Fi needs ACKs (slide 60)

- **Wired Ethernet:** if a frame is sent without a collision, it's **assumed to have been received correctly**. No ACKs (Lesson 19).
- **Radio:** the environment is full of **noise and interference**, so that assumption doesn't hold.

So **802.11 uses positive acknowledgement: every received frame must be ACKed.**

```
Sender                  Receiver
MAC frame ────────────────>
          <──────────────── ACK          ✓ success

MAC frame ──────✗                         frame lost
   (no ACK arrives within a fixed time → assume it was lost → resend)
MAC frame ────────────────>
          <──────────────── ACK
```

If no ACK arrives within a **fixed time**, the frame is **assumed lost** and **retransmitted**. Either the frame or the ACK might have been lost, and the sender can't tell which. This is the same **timeout** idea as Stop-and-Wait ARQ in Lesson 15.

| | Wired Ethernet | Wi-Fi (802.11) |
|---|---|---|
| Errors | Rare | Common (noise, interference) |
| ACK every frame? | ❌ No | ✅ Yes |
| Lost frame | Left to higher layers | Resent at the MAC layer after a timeout |

## 5. MAC access modes (slide 61)

| Mode | Full name | How it works |
|---|---|---|
| **DCF** | Distributed Coordination Function | **Contention-based.** Uses **CSMA/CA**: listen before sending, with a random backoff. The **most common** mode. |
| **PCF** | Point Coordination Function | **Contention-free.** The AP acts as the point coordinator and controls who may send. Not widely implemented. |
| **HCF** | Hybrid Coordination Function | A **mix** of contention and contention-free access. The basis of some **QoS** (quality of service) mechanisms. |

### CSMA/CA vs CSMA/CD

| | CSMA/CD (Ethernet) | CSMA/CA (Wi-Fi) |
|---|---|---|
| Last two letters | **Collision Detection** | **Collision Avoidance** |
| Listen before sending | ✅ | ✅ |
| Random wait (backoff) | After a collision | ✅ Random backoff |

> *Beyond the notes:* the slide only says "listen before send, random backoff". The usual reason Wi-Fi **avoids** collisions instead of **detecting** them is that a radio can't easily listen while it transmits (its own signal drowns out everyone else's), and because of the hidden node problem below, the sender might not hear the collision anyway.

## 6. Hidden and exposed nodes (slides 62–63)

On a cable, every node hears every transmission. With radio, each node only hears nodes **within its range**, so "the channel is idle" can mean different things to different nodes.

```
    Coverage of node 1        Coverage of node 3
   (           (                   )           )
   (     1     (        2          )     3     )
   (           (                   )           )
        1 and 2 can hear each other; 2 and 3 can hear each other;
        1 and 3 CAN'T hear each other
```

### Hidden node problem (slide 62)

- Nodes 1–2 and 2–3 can communicate, but something prevents 1 and 3 from hearing each other.
- Node 1 doesn't know when node 3 is transmitting, and vice versa.
- **Both may send to node 2 at the same time**, causing **interference** at node 2.
- Carrier sensing doesn't help: each one senses the channel as **idle**.

**Result:** collisions that the senders can't detect.

### Exposed node problem (slide 63)

- Node 1 is transmitting (to someone on its far side).
- Node 2 wants to send a frame to node 3.
- Node 2 **senses the medium is busy** (it can hear node 1) and **backs off**.
- But node 3 can't hear node 1, so node 2's frame **would not have caused interference** at node 3. Node 2 waited for nothing.

**Result:** **reduced throughput**, because transmissions that could have happened don't.

| | Hidden node | Exposed node |
|---|---|---|
| What goes wrong | A node **sends when it shouldn't** | A node **doesn't send when it could** |
| Why | It **can't hear** the other sender | It **can hear** a sender that wouldn't actually interfere |
| Effect | **Collisions / interference** | **Wasted capacity / lower throughput** |

> **Analogy:** two people on opposite sides of a wall, both shouting to a friend standing in the doorway.
> - **Hidden:** they can't hear each other, so they both shout at once, and the friend in the doorway can't understand either.
> - **Exposed:** you stay quiet because you hear someone talking in the next room, even though your friend in front of you could have heard you perfectly well.

## 7. Data link summary (slide 64)

This wraps up the whole data link section (Lessons 9–11 and 15–20).

- The **physical layer** offers an **unreliable bit pipe**: each bit has a probability of error **p_b**.
- The **data link layer**:
  - implements **framing** and **error detection**: it knows where a frame starts and ends, and whether it has errors
  - **controls the flow** on a link
  - implements **ARQ** for errors
  - **controls access to the medium**
- **Next:** the **network layer**, which assumes there is **reliable communication between adjacent devices**.

| Data link job | Where you learned it |
|---|---|
| Framing (flags, bit stuffing) | Lesson 11 |
| Error detection (parity, Hamming, CRC) | Lessons 10–11 |
| Flow control (Stop-and-Wait, sliding window) | Lesson 15 |
| ARQ (Stop-and-Wait, Go-back-N, Selective Repeat) | Lessons 15, 16, 18 |
| Medium access (CSMA/CD, token, CSMA/CA) | Lessons 19–20 |

## Quiz

**Q1.** What do STA, AP, BSS and SSID stand for?

<details><summary>Show answer</summary>

**STA** = Station (a user device) · **AP** = Access Point (a station with access to an external network) · **BSS** = Basic Service Set (a group of stations that can communicate) · **SSID** = Service Set Identifier (the network name)
</details>

**Q2.** What's the difference between an independent BSS and an infrastructure BSS?

<details><summary>Show answer</summary>

An **independent (ad-hoc)** BSS has **no AP**: stations talk directly. An **infrastructure** BSS has an **AP**, and traffic goes through it.
</details>

**Q3.** How does an ESS make many access points look like one network?

<details><summary>Show answer</summary>

**Every AP advertises the same SSID**, and the APs are joined by a **distribution system** (usually an Ethernet backbone) that forwards packets between them, so users can move between APs.
</details>

**Q4.** Why does 802.11 ACK every frame when wired Ethernet doesn't?

<details><summary>Show answer</summary>

Radio has **noise and interference**, so a frame that was sent can't be assumed to have arrived. On a cable, a frame sent without a collision is assumed received.
</details>

**Q5.** A Wi-Fi sender gets no ACK. What does it do, and what might have happened?

<details><summary>Show answer</summary>

After a **fixed time**, it assumes the frame was lost and **retransmits** it. Either the **frame** or the **ACK** was lost; the sender can't tell which.
</details>

**Q6.** Which MAC access mode is most common, and what method does it use?

<details><summary>Show answer</summary>

**DCF** (Distributed Coordination Function), using **CSMA/CA**: listen before sending, with a random backoff.
</details>

**Q7.** Node 2 is between nodes 1 and 3, which can't hear each other. Both send to node 2 at the same time. Which problem is this, and what's the effect?

<details><summary>Show answer</summary>

The **hidden node problem**. The two transmissions **interfere** at node 2, and neither sender can sense the other beforehand.
</details>

**Q8.** Node 2 hears node 1 transmitting and holds back its own frame to node 3, even though node 3 can't hear node 1. Which problem is this, and what's the effect?

<details><summary>Show answer</summary>

The **exposed node problem**. Node 2 backs off when it didn't need to, so **throughput is reduced**.
</details>

**Q9.** Which two OSI layers does 802.11 cover?

<details><summary>Show answer</summary>

The **physical** layer and the **data link** (MAC) layer.
</details>

## What to remember

- **802.11** = Wireless LAN · licence-exempt **ISM band** · standardised by the **IEEE** · the **Wi-Fi Alliance** promotes interoperability.
- **STA, AP, BSS, SSID.** Ad-hoc (no AP) vs infrastructure (with an AP).
- **ESS** = several BSSs with the **same SSID**, joined by a **distribution system** (usually Ethernet), allowing mobility.
- 802.11 covers the **physical and data link** layers.
- **Every frame is ACKed**, and a missing ACK means retransmit after a fixed time.
- **DCF** (CSMA/CA, contention, most common) · **PCF** (AP-controlled, rare) · **HCF** (hybrid, for QoS).
- **Hidden node:** can't hear each other → **collisions**. **Exposed node:** backs off unnecessarily → **lower throughput**.
- **Data link jobs:** framing, error detection, flow control, ARQ, medium access.
